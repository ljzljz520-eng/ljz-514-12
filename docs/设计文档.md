# 设计文档（中文）

## 1. 设计目标
- 提供清晰、可用的线路规划交互：选起点/终点 → 一键规划 → 地图与列表同步展示
- 算法与数据解耦：支持从 `edges.csv` 明确定义道路/连接关系，也支持按经纬度自动生成边作为兜底
- 可部署、可复现：`docker compose up -d --build` 一键运行

## 2. API 设计

### 2.1 健康检查
- `GET /api/health`
- 返回：`{ status: "ok", time: "..." }`

### 2.2 节点列表
- `GET /api/nodes`
- 返回：节点数组 `[{ id, name, lat, lng, type?, desc? }, ...]`

### 2.3 路径规划
- `GET /api/path?from=<id>&to=<id>&profile=<comprehensive|distance|less_transfer>`
- `profile` 可缺省，默认 `comprehensive`（综合耗时）
- 成功返回：
  - `startId` / `endId` / `profile` / `profileLabel`
  - `options`：候选路线数组（后端固定同时计算三种偏好并按节点序列去重），每条包含：
    - `profile` / `profileLabel` / `selected`（对应当前偏好）/ `recommended`（固定为综合耗时最优）
    - `totalDistanceMeters` / `totalSeconds` / `transferCount` / `totalClimbMeters` / `totalDescentMeters`
    - `baseSeconds` / `slopeSeconds` / `crowdSeconds` / `transferSeconds`（综合耗时拆解）
    - `highlight`：该路线一句话亮点；`reasons`：相对推荐路线的差异解释
    - `pathNodeIds` / `pathNodes` / `segments`
  - `segments`：逐段连接指标（距离、基础耗时、坡度/上/下坡、坡度附加、拥挤等级与延误、
    是否换乘与等候、通行方式、备注）
  - `summary`：为什么默认推荐这条路，以及与其他走法的对比
  - 顶层同时保留 `totalDistanceMeters` / `pathNodeIds` / `pathNodes` /
    `segmentDistanceMeters` 等扁平字段，向后兼容
- 失败返回：`{ error: "...中文错误信息..." }`

### 2.4 权重模型
- 每条边记录五个维度：距离、基础步行/乘车耗时、坡度、是否需要换乘（含等候）、拥挤程度
- 综合耗时（秒）= 基础耗时 + 坡度附加（上坡 4 秒/米、下坡 0.4 系数）
  + 拥挤延误（0/10/20/35/55%）+ 换乘等候
- 其他偏好：`distance` 仅按真实距离；`less_transfer` 在综合耗时上对每次换乘加 600 秒惩罚
- 权重换算集中在 `EdgeCost`，便于统一调参与向用户解释

## 3. 前端交互设计

### 3.1 控制面板
- 起点/终点下拉选择（支持搜索）
- 寻路偏好切换：综合耗时（默认）/ 最短距离 / 最少换乘
- 交换起终点、清空选择
- 结果区展示：
  - 候选方案卡片（推荐标记、综合耗时、距离、亮点与“为什么不选它”的差异点）
  - 综合耗时构成条（基础/坡度/拥挤/换乘四部分）
  - 途经景点与逐段明细（通行方式、距离、耗时、坡度方向、拥挤、换乘、路况备注）

### 3.2 地图交互
- 渲染所有景点 Marker
- Marker Popup 支持“一键设为起点/终点”
- 选中方案按通行方式逐段着色（步行蓝、公交紫、轨道青），悬停显示该段耗时构成
- 其他走法用灰色虚线对照，配路线图例

## 4. 数据与容错设计

### 4.1 CSV 数据
- `nodes.csv`：必须存在且包含列 `id,name,lat,lng`（其他列可选）
- `edges.csv`：可选；至少包含 `from,to`；权重列 `distance_meters` / `walk_seconds` /
  `slope_percent` / `transfer` / `transfer_seconds` / `crowd_level` / `mode` / `note` 均可缺省；
  旧列名 `distanceMeters` / `weight_meters` / `weightMeters` 仍然兼容

### 4.2 容错策略
- 后端：`DataLoader` 对缺列/坏行进行跳过或给出明确的中文异常提示
- 前端：对节点 API 返回进行结构校验与清洗，避免脏数据触发运行时崩溃
- UI：ErrorBoundary 捕获不可预期异常并提示刷新重试

## 5. 性能与扩展
- 节点数量较小（景点级别）时，Dijkstra 在内存中运行即可满足交互性能
- 未来扩展点：
  - 引入真实道路网（大量边）时，可考虑启发式算法（A*）或预计算缓存
  - 拥挤度/耗时接入实时数据（分时、节假日），并支持票价、无障碍（电梯/台阶）等更多偏好
