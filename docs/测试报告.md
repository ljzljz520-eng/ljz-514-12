# 测试报告（中文）

## 1. 测试范围
- Docker 一键启动（前端/后端/数据库）
- 后端接口：健康检查、节点列表、最短路径
- 前端页面：加载节点、选择起终点、地图渲染与路径展示
- 数据文件：`nodes.csv` 导入、`edges.csv` 读取与优先级

## 2. 自测环境
- macOS + Docker Desktop
- 前端：Nginx 静态站点（容器）
- 后端：Java 17（容器）
- 数据库：PostgreSQL 15（容器）

## 3. 自测用例与结果

### 3.1 服务可用性
- 访问前端首页：`http://localhost:3514/`（通过）
- 健康检查：`GET http://localhost:8514/api/health`（通过）

### 3.2 节点数据
- `GET /api/nodes` 返回节点数组且包含 `id/name/lat/lng`（通过）

### 3.3 路径规划
- 正常参数：`GET /api/path?from=JIEFANGBEI&to=HONGYADONG` 返回路径与距离（通过）
- 非法节点：`GET /api/path?from=NOPE&to=HONGYADONG` 返回 400 且中文错误（通过）
- 缺省 `profile` 时按综合耗时返回，`recommended` 标记在综合耗时最优方案上（通过）
- 以“洪崖洞 → 南山一棵树”为例：综合耗时推荐“洪崖洞→解放碑→南山（公交，约 62 分钟，1 次换乘）”；
  最短距离给出“洪崖洞→南山（步行 4100 m，累计爬升约 574 米，约 121 分钟）”，
  `reasons` 正确说明少走 950 米但多耗时约 59 分钟、多爬升 574 米（通过）

### 3.4 edges.csv 优先级
- 当 `edges.csv` 存在且包含 `from,to` 时，构图优先使用边数据；缺失权重则按经纬度计算（通过）
- 当 `edges.csv` 缺失或为空时，自动生成边并保证尽可能连通（通过）

### 3.5 多维权重与偏好（单元测试 GraphServiceTest，通过）
- 距离更短但 15% 陡坡 + 非常拥挤的直连，会被综合耗时绕行避开；最短距离仍选直连
- 公交方案在综合耗时下更快、最少换乘偏好下步行直达胜出，证明换乘惩罚生效
- `EdgeCost` 口径：上坡 100 米（10%×1000 m）= 400 秒，同坡度下坡 = 160 秒；拥挤 2 级 = 基础耗时 ×20%
- 每个方案返回逐段 `segments`（基础/坡度/拥挤/换乘拆解）与方案间中文对比，前端可直接渲染解释

## 4. 已知限制
- 地图瓦片依赖 OpenStreetMap 外部网络；在无外网环境下瓦片可能加载失败，但不影响接口与规划逻辑
- `pnpm` 版本更新提示属于正常提示信息，不影响构建；建议保持 lockfile 与 `package.json` 同步
