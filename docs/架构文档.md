# 架构文档（中文）

## 1. 项目概述
本项目为“重庆旅游线路规划系统”，提供景点节点展示、起终点选择与最短路径规划能力。

系统由三部分组成：
- 前端：单页应用，负责地图可视化与交互（景点标注、路径线段、规划结果列表）
- 后端：HTTP API 服务，负责数据加载、图构建与最短路计算
- 数据库：PostgreSQL，用于持久化节点数据（首启自动从 `nodes.csv` 导入）

## 2. 模块划分

### 2.1 前端（`frontend/`）
- 页面与布局：`Home` 组合侧边栏控制面板与地图
- 状态管理：基于 Zustand 的 `useTravelStore`，集中管理节点、起终点、路径结果
- 地图渲染：基于 React-Leaflet，渲染 Marker / Polyline / Popup
- UI 组件库：Ant Design，已配置中文语言包（locale）

### 2.2 后端（`backend/`）
- 入口：`Main` 启动内置 HTTP Server，注册路由并初始化服务依赖
- Handler：`RequestHandler` 负责 API 路由分发、参数校验、JSON 输出与 CORS
- Service：
  - `DataLoader`：读取 `nodes.csv` / `edges.csv`
  - `NodeRepository`：通过 Hibernate ORM 将节点存入 PostgreSQL 并提供查询
  - `GraphService`：构建图结构并运行 Dijkstra 最短路

### 2.3 数据层
- `nodes.csv`：节点主数据（必需）
- `edges.csv`：边数据（可选；存在时优先使用）
- PostgreSQL：节点持久化，避免每次重启重复解析与便于扩展

## 3. 数据流与调用链

### 3.1 节点加载
1) 后端启动：
- 若数据库无节点：读取 `nodes.csv` 并写入 PostgreSQL
- 读取 `edges.csv`（若存在）用于图构建，否则按地理距离自动生成边
2) 前端启动：请求 `GET /api/nodes` 获取节点列表并渲染

### 3.2 路径规划
1) 前端提交起终点：`GET /api/path?from=<id>&to=<id>`
2) 后端：
- 校验参数与节点存在性
- Dijkstra 按“综合耗时”计算最优路线；再用 Yen 算法求若干条次优路线作为备选
- 返回：汇总指标（综合耗时/纯步行耗时/总距离/换乘次数/最大坡度/平均拥挤）、每段路的明细属性、备选路线列表
3) 前端：渲染路径线段（按拥挤度着色、换乘段虚线）、分段明细与推荐/备选对比说明

## 4. 图构建策略
系统支持两种图数据来源：
- **显式边（优先）**：`edges.csv` 提供 `from,to` 及路况属性 `distance_meters,walk_minutes,slope_percent,transfers,crowding`；属性缺失时按经纬度距离推算
- **自动生成边（兜底）**：当 `edges.csv` 缺失或为空时，按地理距离为每个节点选择近邻（可配置），并可启用连通性补齐

综合耗时权重（寻路使用的边权）：

```
cost = walk_minutes × (1 + 坡度惩罚系数 × slope_percent) × (1 + 拥挤惩罚系数 × (crowding - 1)) + 换乘惩罚 × transfers
```

相关环境变量：
- `GRAPH_K`：自动生成边时每点近邻数（默认 6）
- `GRAPH_MAX_DISTANCE_METERS`：自动边最大连接距离（默认 15000）
- `GRAPH_ENSURE_CONNECTIVITY`：使用 `edges.csv` 时是否强制连通性补齐（默认 true）
- `ROUTE_WALK_SPEED_M_PER_MIN`：步行耗时缺失时的推算步速（默认 75 米/分钟）
- `ROUTE_SLOPE_PENALTY_PER_PERCENT`：每 1% 坡度的耗时惩罚比例（默认 0.06）
- `ROUTE_CROWD_PENALTY_PER_LEVEL`：每级拥挤的耗时惩罚比例（默认 0.06）
- `ROUTE_TRANSFER_PENALTY_MINUTES`：每次换乘的惩罚分钟数（默认 10）
- `ROUTE_ALTERNATIVES`：返回的备选路线数量（默认 2）

## 5. 部署架构（Docker Compose）
- `frontend`：Nginx 提供静态资源与 `/api` 反代到 `backend`
- `backend`：Java 运行时镜像，暴露 8080（宿主映射为 8514）
- `db`：PostgreSQL 15，带健康检查与数据卷

端口：
- 前端：`3514`
- 后端：`8514`
- 数据库：`5514`
