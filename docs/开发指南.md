# 开发指南（中文）

## 1. 目录结构
- `frontend/`：前端（Vite + React）
- `backend/`：后端（Java + Maven）
- `docs/`：项目文档
- `docker-compose.yml`：一键编排

## 2. 本地启动（推荐 Docker）
在项目根目录执行：
```bash
docker compose up -d --build
```

访问：
- 前端：`http://localhost:3514/`
- 后端：`http://localhost:8514/api/health`

## 3. 前端开发

### 3.1 安装依赖
```bash
pnpm -C frontend install
```

### 3.2 开发模式
```bash
pnpm -C frontend dev
```

### 3.3 构建
```bash
pnpm -C frontend run build
```

## 4. 后端开发

### 4.1 说明
本环境若未配置 `JAVA_HOME`，建议通过 Docker 构建/运行后端。

### 4.2 Docker 构建
```bash
docker compose build backend
```

## 5. 数据文件维护

### 5.1 节点（必需）
路径：`backend/src/main/resources/nodes.csv`

必需列：
- `id`：节点唯一 ID（建议大写英文 + 下划线）
- `name`：展示名称（中文）
- `lat` / `lng`：经纬度（小数）

可选列：`type`、`desc`

### 5.2 边（可选）
路径：`backend/src/main/resources/edges.csv`

必需列：
- `from`：起点 ID
- `to`：终点 ID

多维权重列（均可缺省，缺省时按默认模型估算）：
- `distance_meters`：真实步行/道路距离（米）；缺省取两点球面距离
- `walk_seconds`：步行或乘车基础耗时（秒）；缺省按 1.3 m/s 步行速度估算
- `slope_percent`：平均坡度百分比，沿 CSV 行方向为正表示上坡、负表示下坡；
  综合耗时中上坡按每米 4 秒、下坡按 0.4 系数折算（反向边自动取反）
- `transfer`：是否需要换乘（`true`/`false`），如公交、轨道、索道、大扶梯
- `transfer_seconds`：换乘等候时间（秒），缺省为 300
- `crowd_level`：拥挤程度 0-4（畅通 / 轻微 / 中度 / 拥挤 / 非常拥挤），
  分别按基础耗时的 0% / 10% / 20% / 35% / 55% 计入延误
- `mode`：通行方式 `walk` / `bus` / `rail` / `cableway` / `escalator`
- `note`：该连接的真实路况备注（展示在页面上，用于解释结果）

示例：

```csv
from,to,distance_meters,walk_seconds,slope_percent,transfer,transfer_seconds,crowd_level,mode,note
HONGYADONG,NANSHAN,4100,4500,14,false,,1,walk,经上新街盘山上山，累计爬升约570米
JIEFANGBEI,NANSHAN,4300,1500,0,true,480,3,bus,南山旅游专线，候车约8分钟
```

综合耗时口径（`EdgeCost`）：

```
综合耗时 = 基础耗时 + 坡度附加 + 拥挤延误 + 换乘等候
```

注意：如果 `edges.csv` 缺失或为空，系统会按地理距离自动生成边（默认平路、畅通、步行）。

## 6. 实施计划（合并）

### 6.1 目标
- 交付可运行的“重庆旅游线路规划系统”，支持一键启动、节点展示、路径规划与结果可视化

### 6.2 范围
- 前端：地图与控制面板、状态管理、错误兜底、中文化
- 后端：CSV 数据加载、数据库持久化、图构建、最短路径 API
- 运维：Docker Compose 一键启动、前端反代后端、环境变量配置

### 6.3 关键决策
- 数据输入采用 CSV（`nodes.csv` / `edges.csv`），兼容无边数据时的自动构图兜底
- 后端图算法采用 Dijkstra（节点规模小、实现清晰、可解释）
- 前端使用 Ant Design + React-Leaflet，结合 ErrorBoundary 保障稳定性

### 6.4 验收标准
- `docker compose up -d --build` 后：前端可访问、后端健康检查通过
- `/api/nodes` 返回非空节点列表
- `/api/path` 能返回可解释的路径结果；非法参数返回中文错误
- 文档齐全：架构/设计/开发/测试/用户手册/README

## 7. 任务清单（合并）

### 7.1 已完成
- 前端：修复构建与运行时异常，完成地图与路径展示
- 后端：实现 CSV 加载、数据库 Seed、最短路 API
- 运维：Docker Compose 编排（frontend/backend/db），前端 `/api` 反代
- 中文化：前端组件库 locale、后端中文错误信息
- 数据：集成 `edges.csv`（存在则优先使用，否则自动构图）
- 权重：边记录距离、步行耗时、坡度、换乘（含等候）、拥挤程度五个维度；
  默认按综合耗时（`EdgeCost`）Dijkstra 寻路，支持最短距离 / 最少换乘偏好；
  返回候选方案对比、逐段耗时拆解与中文解释，前端方案卡 + 地图着色可视化

### 7.2 可选优化
- 拥挤度/耗时接入分时实时数据，新增票价、无障碍（电梯/台阶）等权重维度
- 缓存热门起终点的最短路径结果
- 离线底图或自建瓦片服务，解决无外网场景
